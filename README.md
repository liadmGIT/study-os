# מערכת הלימודים 🎓

מערכת אישית לניהול הלימודים שמתחברת ל-Moodle של אוניברסיטת בן-גוריון ומתעדכנת לבד.
כל המטלות, הדדליינים, ההקלטות וההודעות מכל הקורסים נמצאים במקום אחד, יחד עם המשימות האישיות שלך.

## מה יש במערכת

**מנהל משימות חכם**
- כל המטלות והבחנים מכל הקורסים נמצאים ברשימה אחת, יחד עם משימות אישיות שאתה מוסיף.
- המשימות ממוינות לפי דחיפות: באיחור, דחוף, השבוע, בהמשך. אפשר לסנן לפי קורס ולחפש.
- **תתי־משימות.** הכפתור "פצל לשאלות" מחלק מטלה ל-N שאלות בלחיצה אחת, וסרגל מראה כמה מהן כבר עשית.
- **התראה "עוד לא התחלת"** כשהדדליין מתקרב ואין שום התקדמות. במטלה גדולה, לפי הערכת הזמן שלך, ההתראה מגיעה מוקדם יותר.
- **זיהוי הגשה.** כשמשהו מוגש ב-Moodle, המשימה עוברת לסטטוס "הוגש", וכשמגיע ציון הוא מוצג עליה.
- **זיהוי תאריך שזז.** כשתאריך הגשה משתנה, המשימה מקבלת תג "התאריך זז" עם התאריך הישן והחדש, ונשלחת התראה.

**סנכרון אוטומטי עם Moodle**
- הסנכרון רץ כל 20 דקות ביום ופעם בשעה בלילה. יש גם כפתור "סנכרן עכשיו".
- המערכת מושכת את הקורסים, המטלות, הבחנים, ההגשות, ההרצאות, המצגות, הקבצים, ההקלטות וההודעות מהמרצים.
- הסנכרון הראשון רק שומר את המצב הקיים. מהסנכרון השני ואילך, כל דבר חדש או שהשתנה מופיע ב"מה חדש".

**מעקב הרצאות**
- המערכת מזהה הקלטות לבד: קישורי Zoom, YouTube, Panopto ו-Kaltura, קבצי וידאו, ושמות כמו "הקלטת הרצאה 3".
- לכל הקלטה אפשר לסמן נצפה או לא נצפה, ולשמור **באיזו דקה עצרת**.
- **מד פיגור** לכל קורס מראה כמה הרצאות אתה מאחור וכמה שעות צפייה זה.
- **תוכנית השלמה** מחלקת את ההרצאות שפספסת לפי זמן יומי שאתה קובע, והן מופיעות בלוח השבועי.
- לכל הרצאה יש מקום להערות וסיכום (Markdown), והמצגת של אותו שבוע מקושרת אליה.

**ועוד**
- **לוח שבועי.** גוררים משימה ליום שבו תעבוד עליה.
- **Google Calendar.** כל הדדליינים מופיעים ביומן שלך דרך מנוי לקישור.
- **הורדת קבצים אוטומטית.** כל מצגת וקובץ חדשים יורדים לשרת, מסודרים לפי קורס ושבוע. אפשר להוריד קורס שלם כקובץ ZIP.
- **התראות לטלפון** (Web Push), עם שעות שקט.
- ממשק בעברית, שעובד במחשב ובטלפון. אפשר להוסיף אותו למסך הבית כמו אפליקציה.

## איך זה בנוי

```
Moodle (moodle.bgu.ac.il)
   ▲  ה-API של אפליקציית Moodle לנייד, כל 20 דקות
   │
שרת (Node 22 + Fastify + SQLite)  ──►  התראות לטלפון (Web Push)
   │                              ──►  יומן (קישור ICS ל-Google Calendar)
   ▼
ממשק ווב (React, עברית, PWA)
```

- המערכת משתמשת באותו API של אפליקציית Moodle הרשמית לנייד, ולא "גורדת" את האתר.
- **הסיסמה שלך לא נשמרת.** משתמשים בה פעם אחת כדי לקבל מפתח גישה (token), והמפתח נשמר מוצפן (AES-256-GCM).
- הכניסה למערכת עצמה מוגנת בסיסמה נפרדת שאתה קובע (`APP_PASSWORD`).

## צעד 1: בדיקה מהמחשב שלך (5 דקות)

לפני ההעלאה לשרת, כדאי לוודא ש-Moodle של בן-גוריון מאפשר גישה דרך ה-API.
צריך [Node.js 22](https://nodejs.org) מותקן.

```bash
git clone <כתובת ה-repo שלך>
```

```bash
cd study-os
```

```bash
npm install
```

```bash
npm run moodle:probe
```

הסקריפט מבקש שם משתמש וסיסמה של האוניברסיטה. הם נשלחים רק ל-Moodle ולא נשמרים. בסוף הוא מראה:

- אם ההתחברות עם שם משתמש וסיסמה עובדת.
- אילו חלקים מה-API פתוחים: ✅ פתוח, ⚠️ חסום.
- את הקורסים, המטלות וההקלטות שהמערכת תראה.

אם כתוב שההתחברות היא "דרך הדפדפן (SSO)", במערכת תשתמש באפשרות **"דרך הדפדפן"**, ולא בשם משתמש וסיסמה.

## צעד 2: העלאה לשרת ב-Railway (בערך 5$ לחודש)

1. היכנס ל-[railway.com](https://railway.com) ← **New Project** ← **Deploy from GitHub repo**, ובחר את ה-repo. Railway מזהה את ה-`Dockerfile` לבד.
2. בלשונית **Variables** הוסף:

   | משתנה | ערך |
   |---|---|
   | `APP_PASSWORD` | סיסמה לכניסה למערכת (תבחר אחת חזקה) |
   | `ENCRYPTION_KEY` | מחרוזת אקראית ארוכה |
   | `SESSION_SECRET` | מחרוזת אקראית ארוכה, שונה מהקודמת |

   אפשר ליצור מחרוזת אקראית עם הפקודה הזו (או סתם 40 תווים אקראיים):

   ```bash
   openssl rand -base64 32
   ```

3. **Volume:** לחץ על השירות ← **Settings** ← **Volumes** ← **Add Volume**, עם Mount path `/data`. בלי זה, הנתונים נמחקים בכל עדכון.
4. **Settings** ← **Networking** ← **Generate Domain**. הוסף את הכתובת שקיבלת כמשתנה `PUBLIC_URL`, למשל `https://study-os-production.up.railway.app`.
5. פתח את הכתובת, היכנס עם `APP_PASSWORD`, ועבור ל**חיבור ל-Moodle**.
   - ✅ מופיע "השרת מגיע ל-Moodle": מתחברים, והסנכרון הראשון מתחיל.
   - ❌ מופיע "השרת לא מצליח להגיע": כנראה האוניברסיטה חוסמת כתובות מחוץ לישראל. עבור לצעד 2ב.

## צעד 2ב: אם Moodle חוסם את השרת, שרת בתל אביב

אותה מערכת בדיוק, רק על שרת קטן באזור ישראל: Google Cloud `me-west1` או AWS `il-central-1`.

1. צור שרת וירטואלי: Debian או Ubuntu, 1GB זיכרון מספיק. אפשר בו תעבורת HTTP ו-HTTPS.
2. התקן Docker:

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

3. הורד את הקוד והכן הגדרות:

   ```bash
   git clone <כתובת ה-repo שלך> study-os
   ```

   ```bash
   cd study-os && cp .env.example .env
   ```

4. ערוך את `.env`: מלא `APP_PASSWORD`, `ENCRYPTION_KEY`, `SESSION_SECRET`, `PUBLIC_URL`, והוסף שורה `DOMAIN=...`.
   - אין לך דומיין? אפשר להשתמש ב-`<IP-של-השרת>.sslip.io`, למשל `34.165.10.20.sslip.io`.
   - Caddy מוציא תעודת HTTPS לבד.
5. הפעל:

   ```bash
   docker compose up -d --build
   ```

## צעד 3: בטלפון

- **אנדרואיד (Chrome):** פתח את האתר ← תפריט ← **התקן אפליקציה**.
- **אייפון (Safari):** שיתוף ← **הוסף למסך הבית**. פתח את האפליקציה מהמסך הראשי (התראות באייפון עובדות רק כך).
- **בשני המקרים:** **הגדרות** ← **התראות** ← **הפעל התראות** ← **שלח בדיקה**.

## Google Calendar

**הגדרות** ← **Google Calendar** ← **העתק**. אחר כך ב-Google Calendar: **הוספת יומן** ← **מכתובת URL** ← מדביקים.

Google מרענן יומנים כאלה כל כמה שעות, כך ששינוי ברגע האחרון יכול להופיע שם באיחור. במערכת עצמה ובהתראות הוא מופיע מיד.

## הרצה מקומית (הדגמה ופיתוח)

אפשר לראות את כל המערכת עם Moodle מדומה, בלי להתחבר לאוניברסיטה:

```bash
npm install
```

```bash
npm run dev:mock
```

1. פתח http://localhost:5173 והיכנס עם הסיסמה `dev`.
2. ב"חיבור ל-Moodle" התחבר עם `student` / `password`.
3. כדי לראות איך נראים עדכונים, אפשר "לגרום למרצה לשנות דברים": להזיז דדליין, להעלות הקלטה ולפרסם הודעה.

   ```bash
   curl -X POST http://127.0.0.1:4100/__mock/scenario
   ```

4. אחר כך לחץ "סנכרן עכשיו".

מול ה-Moodle האמיתי מריצים `npm run dev`, וצריך להגדיר `APP_PASSWORD` אם רוצים סיסמה אחרת מ-`dev`.

### בדיקות

```bash
npm test
```

```bash

```

הבדיקות מריצות סנכרון מלא מול ה-Moodle המדומה:

- אחריו "המרצה" משנה דברים, ובסנכרון השני הם מזוהים: התאריך שזז, ההקלטה החדשה, ההודעה וההגשה.

## משתני סביבה

| משתנה | חובה | תיאור |
|---|---|---|
| `APP_PASSWORD` | כן | הסיסמה לכניסה למערכת |
| `ENCRYPTION_KEY` | מומלץ | מפתח להצפנת הטוקן של Moodle. אם חסר, נוצר אחד ונשמר ב-`/data` |
| `SESSION_SECRET` | מומלץ | מפתח לחתימת ההתחברות. אם חסר, נוצר ונשמר ב-`/data` |
| `PUBLIC_URL` | מומלץ | הכתובת הציבורית, לקישורים ביומן ובהתראות |
| `MOODLE_URL` | לא | ברירת מחדל: `https://moodle.bgu.ac.il/moodle` |
| `DATA_DIR` | לא | איפה שומרים את מסד הנתונים והקבצים. ב-Docker: `/data` |
| `VAPID_SUBJECT` | לא | כתובת `mailto:` עבור התראות push |

## בעיות נפוצות

- **"צריך להתחבר מחדש ל-Moodle".** הטוקן של Moodle פג. זה קורה מדי פעם (Moodle קובע לכמה זמן הטוקן תקף). התחבר שוב בהגדרות; הנתונים נשמרים.
- **הקלטה לא זוהתה, או קובץ זוהה בטעות כהקלטה.** בעמוד הקורס, ליד כל פריט, אפשר לשנות את הסיווג. השינוי נשמר.
- **קורס ישן מופיע, או קורס חסר.** **הגדרות** ← **קורסים במעקב**.
- **הסנכרון "חלקי".** בהגדרות, תחת **סנכרון**, מופיע מה נכשל. בדרך כלל אלה חלקים של ה-API שהאוניברסיטה לא פתחה. כרטיס החיבור מראה בדיוק מה חסר.

## מבנה הקוד

```
server/
  src/moodle/     התחברות ל-Moodle וקריאות ל-API
  src/sync/       מנוע הסנכרון: קורסים, תוכן, מטלות, הודעות, קבצים, זיהוי שינויים
  src/domain/     דחיפות, "עוד לא התחלת", מעקב ופיגור בהרצאות, תוכנית השלמה
  src/notify/     כללי התראות ושליחת push
  src/calendar/   קובץ היומן (ICS)
  src/routes/     ה-API של הממשק
  test/           Moodle מדומה ובדיקות
  scripts/probe.ts  בדיקת חיבור ל-Moodle האמיתי
web/
  src/pages/      המסכים: בית, משימות, הרצאות, שבוע, קורסים, קבצים, עדכונים, הגדרות
  src/components/ רכיבי ממשק
  public/sw.js    service worker להתראות
```
